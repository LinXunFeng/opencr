# 失败审查运行重新触发

状态：整体方案已确认，已在功能分支 `feat/retry-failed-runs` 实现。

## 已确认

- 仅明确失败的 ReviewRun 可重新触发，不包含 Stale 或成功但带降级的运行。
- 重新触发时可选择最新 MR 的全量变更，或原失败运行对应的完整提交区间；后者不是仅补跑失败文件或步骤。
- 例如 A→B 的增量审查失败后 MR 推进到 C：全量审查当前 C 的 MR 全部变更；原范围仍审查 A→B。
- 增加允许 Guest 重新触发的独立开关，默认关闭，仅 Admin 可以在后台即时修改。
- Guest 重新触发必须同时满足游客访问已开启、游客重新触发已开启，权限由服务端校验。
- 历史失败运行缺少原始提交区间或必要参数时，仅允许最新全量；原失败范围选项禁用并说明原因。
- 每次重试创建新的 ReviewRun，关联原失败运行，保留原记录。
- 重试入口在同一个 MR 已有审查正在运行时拒绝触发，返回正在运行的记录入口；同时点击重试只创建一次，防重覆盖多个服务进程。
- 并发限制仅约束重试入口，后续 webhook 和原有手动入口仍可启动运行，不保证同 MR 全程只有一个运行。
- Stale 仍阻止重试，不凭心跳超时推断旧运行已终止；实际中断但仍标记 running 的记录也会阻止重试，自动恢复机制不在本次范围内。
- 保留原失败运行已投递的评论，新运行正常投递，首版接受可能重复的评论。
- 仅允许对仍处于 opened 状态的 MR 重新触发。
- 原范围重试沿用原运行的审查模式与保存的原始技能选择参数，使用当前模型、凭据及技能内容重新匹配；允许实际命中技能变化，不承诺复现历史产出。
- 原提交无法获取时明确报错，不自动切换为最新全量。
- 最新全量使用当前配置，重试弹窗不增加审查模式、技能或模型设置。
- 入口放在失败运行详情页。原范围可用时默认选择原范围，否则默认最新全量。
- 弹窗提示将创建新的审查运行且可能产生重复评论；提交成功后跳转新运行。

## 实施与验证

- 已从 main 创建功能分支 `feat/retry-failed-runs`，携带本次设计文档与术语修改。
- 新入口通过 runner 执行，不复制审查逻辑；新增运行保存原范围重试所需的提交区间与原始选择参数。
- 模型变更配套 Alembic 迁移；后台即时开关沿用现有设置持久化方式，同步修订 ADR 0002 中仅允许游客访问开关使用数据库的例外说明。
- 验证管理员与游客开关组合、运行状态与 MR 状态限制、两种范围、历史记录兼容、原提交不可用、运行关联及跨进程重复触发。
- 运行后端测试、迁移一致性检查与前端构建，不提交构建产物。

## 消融结论

- 保留范围快照、原运行关联、服务端权限和跨进程重试防重，它们分别支撑已确认的行为。
- 不引入任务队列、全入口互斥、自动重试、Stale 自动恢复、断点续跑、评论去重或历史技能内容快照。
- 使用现有 runner、设置存储与运行详情页，不为重试增加独立执行框架或配置面板。

## 实现前已知约束

- 当前 ReviewRun 未保存原始提交区间，手动触发默认读取当前 MR 的全部变更。
- 失败运行可能已经投递部分评论，重新审查可能产生重复评论。
- 当前没有同一 MR 的跨进程并发防重。
- Stale 是读取时根据心跳计算的展示状态，旧运行可能恢复；当前没有取消或阻止旧运行继续投递的机制。
- 全入口互斥将影响连续 push 的合法增量事件；当前没有队列保存被阻止事件的提交区间。
- 历史 review_skills 是实际命中的技能集合，不等于原始选择参数；当前执行路径按技能目录及模型自动匹配。
- 游客设置持久化方式需评估现有 ADR 0002 对数据库配置例外的限制。

本轮已进行设计层面的消融审查，去掉不必要的抽象和设计；实现完成后再次审查。仅在满足仓库 ADR 条件时新增或修订 ADR。
