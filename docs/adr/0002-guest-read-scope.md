# Guest 可以看状态，但看不到审查发现的正文

后台默认允许未登录的 Guest 浏览，目的是让同事无需账号即可查看审查服务的运行状态。
但 Finding 正文包含 AI 对私有仓库代码的具体描述（文件路径、行号、问题与修复建议），
而 webhook 端口按部署方式通常是内网可达的、`admin.bind_local_only` 默认为 `false`。
因此我们把 Guest 的可见范围划在 Finding 正文之外：状态、进度与聚合统计对 Guest 开放，正文必须登录。

## Considered Options

- **Guest 看全部只读内容，默认开启**：最省事，但等于让内网任何能访问该端口的人无凭据读到全部审查内容；
  且开启后台的人多半不会意识到自己顺带把全部审查内容也公开了。
- **Guest 看全部只读内容，默认关闭**：安全，但违背"方便同事直接查看状态"的初衷——需要有人先去改配置才有用。
- **Guest 只看控制台聚合数字**：过窄，看不到具体哪次审查失败了，排查价值大打折扣。
- **Guest 看状态与聚合统计，不看 Finding 正文，默认开启**（选中）：完整满足"看状态"，同时不暴露代码细节。

## Consequences

- **打码必须在服务端完成。** 前端隐藏不是安全边界——接口照样能取到正文。
  凡是可能返回 `finding.body` 的接口，在身份为 Guest 时必须在序列化前剔除该字段。

- 因为可见范围已经排除了敏感内容，**默认开启是安全的**。这条因果关系是本决定成立的前提：
  若将来有人扩大 Guest 的可见范围，必须同时重新评估默认值。

- Guest 是**身份的缺席**，不是一种账号。系统里只有一个 Admin 账号，不存在 Guest 账号，
  也不存在角色表。任何"再加一种角色"的需求都应先回到这里，而不是顺手加一个 role 字段。

- 游客权限开关（`guest_read`、`guest_retry`、`survey_guest_read`，以及下文巡检单页的两个开关）存在数据库而非 `config.yaml`。
  原因是它的使用场景天然是临时性的（"今天有外部人员来，先关一下"），
  要求改文件加重启就等于没人会用。代价是配置真相分散在两处，因此这个例外仅限游客权限开关。

- 未登录访问者能看到项目路径与 MR 标题。这是"看状态"不可避免的一部分：
  运行列表若不显示是哪个项目的哪个 MR，就失去了意义。若这一点不可接受，应关闭 Guest 访问，
  而不是继续裁剪可见字段——再裁下去这个功能就没有存在价值了。

## 失败审查重新触发权限

游客重新触发是独立的操作权限，默认关闭，且仅在游客浏览也开启时生效。
开启后会消耗模型额度并向 MR 发布评论，因此不能沿用游客浏览默认开启的取舍。
它不扩大 Finding 正文的可见范围；服务端分别校验浏览与触发权限。

配置文件加重启与后台即时开关都可实现权限控制，但管理员需要即时收回此操作权限，
因此沿用现有设置存储，接受配置来源分散的代价；不新增账号、角色表或其他可写配置。

## 巡检单页的游客开关：修复合并请求与仓库负责人

「修复合并请求」（列表与修复详情）与「仓库负责人」各有一个游客开关（`survey_fix_guest_read`、`repo_owner_guest_read`），
嵌套在游客浏览与游客可见巡检之下，三者同时打开才对游客生效。

这两个开关**扩大了**上文的可见范围：修复详情含问题标题、文件位置、修改说明、diff 与验证过程，diff 就是代码本身；
仓库负责人列出的是具体的人。按上文"扩大范围必须重新评估默认值"的约定，两者**默认关闭**，开启时界面要求确认并写明会暴露什么。

需要它的理由是：合并请求说明里的「修复运行详情」链接指向后台，点进来的多半是没有后台账号的处理人；
负责人配置则方便同事自查某个仓库的修复会指派给谁。

- **两页各一个开关，而不是合成一个**：两页暴露的东西性质不同（代码与人），管理员很可能只想开其中一个。
- **开关打开后只放开读**：发起、中断修复与负责人的增删改仍只有 Admin 能做，`guest_retry` 也不放开它们——都是对外部平台或指派结果的写入。
- **打开后不再逐字段裁剪修复本身**，只去掉两样：问题正文（就是发现正文，上文"必须在服务端剔除"的硬性边界不因这个开关松动）
  与原始作者的邮箱（个人信息，看懂一次修复用不到它）。修改说明、diff 与验证过程不裁：为这两页单独开开关，就是为了让人看到修复本身，
  裁掉 diff 这页就失去了意义。
- 巡检报告里挂在每条发现上的修复记录**不随这个开关放开**：那里与发现正文同处一页，仍按上文的边界只对 Admin。
- 游客打开仓库负责人列表时**不触发**向代码平台补查姓名：游客无需登录，放开后任何人刷新都能让服务端去平台连查一串用户。
