# 巡检的「不再提醒」按问题忽略，由 L2 的模型判断是不是同一个问题

最初的「不再提醒」按指纹生效。指纹是 `仓库 + 文件路径 + 问题类别`，所以忽略一条发现，实际屏蔽的是这个文件里这一类的全部问题，以后同一文件同类的新问题也会被静默丢掉。真实数据里，用户点了两条发现，三轮运行里同一文件的 11 条正确性问题全被藏掉了，其中包括和那两条毫不相干的问题。因此忽略的单位改为**问题**（IgnoredIssue）：**同一个问题每轮的行号与措辞都会变，没有稳定的键能认出它，所以在 L2 取证这个文件时，把已忽略问题交给模型，由模型判断新报出的问题是不是其中之一。**

## Considered Options

- **保留按指纹忽略，只把影响范围说清楚**：改动最小，但用户要的就是"只忽略这一个"，说清楚只是让误伤变得可见，并没有消除它。否决。
- **把行号或标题哈希加进忽略的键**：完全确定性，但行号每周漂移（实测同一个问题三轮分别在第 53、48、47 行），模型每轮的措辞也不一样（「可选参数被强制解包」与「可选时长参数被强制解包」）。结果是忽略了下一轮又冒出来。同样的理由早已让指纹排除了行号与正文。否决。
- **让模型判断，命中的直接丢弃**：报告更干净，但模型认错时一个真正的新问题会被静默吞掉，事后无从发现。否决。
- **让模型判断，命中的照常入库、关联到已忽略问题、读取时隐藏**（选中）：模型只负责标注 `ignore_ref`，丢不丢由程序决定；被隐藏的发现仍在库里，忽略清单列出每条忽略最近一次隐藏的是哪条，人能核对模型有没有认错。

## Consequences

- 匹配质量取决于模型。它可能把同一个问题认成新的（再报一次，人再点一次即可），也可能把另一个问题认成已忽略的（被隐藏，但在忽略清单的"最近一次隐藏"里看得到）。提示词要求"拿不准时不要填"，宁可多报。程序只接受交给模型的编号，模型编出来的编号一律无效；模型漏标时，按"同指纹且标题规整后完全相同"兜底，相似不算。
- 标记时，保留的运行里同指纹、标题规整后完全相同的发现一起隐藏（同一个问题被原样报了几遍）；换了说法的历史条目不会被追溯隐藏，要等之后的运行由模型认出。
- 只有被 L2 取证的文件才会做匹配。已忽略问题所在的文件这一轮没被取证，它本来也不会被报出来，不需要匹配。
- 台账一行仍是一个指纹，可能合并了好几个问题。只有一行里的问题全部被忽略时，这一行才是「已忽略」；行里还有别的问题时，它仍然「存在」，正文与条数不含被忽略的那些。「已忽略」不再是终态：之后取证了这个文件、模型没再报出这个问题（也没认出它）时，这一行和其他行一样变为「本轮未发现」——按指纹忽略时它会永远停在「已忽略」，因为那一类问题根本不会入库。
- 升级时，旧的指纹级忽略按"该指纹最近一次出现的运行里每个不同标题"换算成问题级（迁移 `b7e4c1a9d2f0`），各轮里同标题的发现一起隐藏，范围只会比原来窄。标题不同的同类发现会重新显示——它们未必是用户想忽略的那个问题。找不到任何记录的旧忽略保留为失效条目，由管理员在忽略清单里删除，而不是在升级时静默丢掉。这次换算无法从数据里还原，降级会把同一指纹下的多条合并回一条指纹级忽略。
- 每个文件最多交给模型 20 条已忽略问题（正文摘要 300 字），这部分会占用 L2 的上下文。
